① QAOA Quantum Approximate Optimization Algorithm

What is it, fundamentally?

💡 Core Idea

QAOA is a hybrid quantum-classical algorithm for solving combinatorial optimization problems. It encodes the problem into a quantum circuit, then uses a classical optimizer to tune the circuit's parameters until the circuit "prefers" the best solution.

Think of it like this: you have a landscape of possible solutions. Classical algorithms walk across it step by step. QAOA uses quantum superposition to explore many solutions at once, and quantum interference to make good solutions more probable and bad ones less probable.

// QAOA Circuit — big picture (p=2 layers) |0...0⟩ → H⊗n → Cost(γ₁) → Mixer(β₁) → Cost(γ₂) → Mixer(β₂) → Measure ↑ ↑ ↑ superpose phases by tunnels everything objective between equally value states
  • Cost layer: rotates each basis state's phase by how good that solution is. Amplifies good ones.
  • Mixer layer: X-rotations that let the state "hop" between solutions — like quantum tunneling.
  • p (depth): more layers → better approximation, but deeper circuit (harder on real hardware).
  • γ, β: the parameters that COBYLA/L-BFGS tune classically to minimize ⟨H⟩.
// Objective function QAOA minimizes: ⟨ψ(γ,β) | H_cost | ψ(γ,β)⟩ → minimize this where H_cost encodes: maximize Σ score_i · x_i subject to Σ x_i = K (exactly K selected) x_i ∈ {0, 1} Equality constraint → QUBO penalty term: +P · (Σ x_i − K)²

What is |ψ(γ,β)⟩ — and what are we actually solving?

📌 In this repo's problem

We have 8 ESOL candidate molecules. We want to select exactly 3 that maximise a combined score (predicted solubility + descriptor desirability). Each possible selection can be written as a binary string of length 8 — e.g. |00010011⟩ means "select molecules 3, 4 and 8". There are 2⁸ = 256 such bitstrings, but only C(8,3) = 56 are valid (exactly 3 selected).

|ψ(γ,β)⟩ is the quantum state the circuit builds and holds. It is a superposition over all 256 bitstrings at once, each carrying a complex amplitude. It is not the answer — it is the vehicle the quantum computer uses to find the answer.

// The quantum state at any point in the circuit: |ψ(γ,β)⟩ = Σₓ αₓ(γ,β) · |x⟩ x = one bitstring, e.g. |00010011⟩ αₓ = complex amplitude of that bitstring |αₓ|² = probability of measuring x γ, β are the parameters COBYLA tunes to make the right bitstring's amplitude as large as possible.

The goal is a classical bitstring — e.g. |00010011⟩ meaning "select molecules 3, 4, 8". That bitstring lives outside the quantum computer, in your measurement result. |ψ⟩ is the vehicle. The bitstring is the destination.

// The full journey in one line: |ψ(γ,β)⟩ → measure → bitstring → decode → selected molecules (quantum state) (classical) (your answer)
🔗 How the pieces connect
  • The optimization problem is classical: maximize Σ score_i · x_i subject to Σ x_i = 3
  • QAOA encodes that into H_cost: each bitstring's amplitude gets phase-shifted by its score
  • |ψ(γ,β)⟩ gets shaped by alternating cost and mixer layers so the best bitstring accumulates the most amplitude
  • You measure and the superposition collapses — the bitstring that comes out is your selection
  • The classical optimizer (COBYLA) tunes γ and β across many circuit runs to maximise the chance of measuring the right answer

The five steps above — superposition → phase shift → mixer → p layers → measure — are exactly what the wave animation shows. Each wave is one basis state. The animation shows how |ψ⟩ gets shaped until the right bitstring dominates. Open the interactive wave explainer →

How people normally use QAOA

  • Portfolio selection (finance: pick K assets that maximize expected return)
  • Max-Cut graph problems (network partitioning, VLSI circuit placement)
  • Job shop scheduling (assign N jobs to M machines with constraints)
  • Drug/molecule selection (select K candidates from scored library)
  • Logistics route optimization (subset of stops to cover under budget)
⚠️ When NOT to use QAOA

QAOA needs the problem formulated as QUBO (binary variables, quadratic terms only). Continuous variables, complex constraints, or huge problem sizes (>50 binary vars) → use classical solvers instead for now. QAOA shines on near-term quantum hardware experiments.

✦ New Example: PK Database Optimization
🔬 QAOA Applied — PK Database

Problem Setup

You have a pharmacokinetics (PK) database with 10 candidate compounds. Each compound has measured PK properties from in-vitro assays. You want to select the top 2–3 molecules for expensive in-vivo studies, balancing multiple PK criteria.

// PK properties per compound (normalized 0–1): oral_bioavailability_i → want HIGH (weight: 3.0) plasma_half_life_i → want ~4-8h (window desirability) clearance_i → want LOW (weight: 2.0) cmax_safety_margin_i → want HIGH (weight: 2.5) protein_binding_i → want < 0.95 (desirability) compound_score_i = 3.0 * bioavail_i + 2.0 * (1 - clearance_i) + 2.5 * safety_i + 1.5 * half_life_desirability_i

QUBO Formulation

// Binary variable: x_i = 1 if compound i is selected maximize Σ score_i · x_i subject to Σ x_i = 2 (or = 3) → QUBO form (penalty P = 5 · max_score): minimize −Σ score_i · x_i + P · (Σ x_i − 2)² Expansion: P · (Σ x_i − 2)² = P · Σ x_i² + 2P · Σᵢ﹤ⱼ x_i·x_j − 4P · Σ x_i + 4P (since x_i² = x_i for binary vars)

QAOA Workflow

// Step-by-step for PK selection Step 1: Score compounds from PK database [C1:0.82, C2:0.61, C3:0.74, C4:0.90, C5:0.55, C6:0.78, C7:0.66, C8:0.88, C9:0.71, C10:0.60] Step 2: Build QuadraticProgram (qiskit_optimization) → add binary vars x0..x9 → set objective: maximize Σ score_i · x_i → add constraint: Σ x_i == 2 Step 3: Convert to QUBO via QuadraticProgramToQubo → constraint becomes penalty in objective → result: 10x10 Q matrix (upper triangular) Step 4: Build QAOA circuit (p=2 or p=3 layers) → H gates on all 10 qubits (superposition) → Cost unitaries encode Q matrix → Mixer unitaries (Rx rotations) Step 5: COBYLA tunes γ=(γ₁,γ₂), β=(β₁,β₂) → minimize ⟨ψ(γ,β)|H_QUBO|ψ(γ,β)⟩ Step 6: Sample 4096 bitstrings from final state → most probable valid bitstring = selection e.g. "0001000100" → C4 + C8 selected ✓
✅ Output

QAOA picks C4 (score 0.90) and C8 (score 0.88) — the pair that satisfies exactly K=2 and maximizes combined PK score. Compare against brute-force (C₂₁₀ = 45 combinations) to verify quality.

② SA/PT Simulated Annealing & Parallel Tempering

Simulated Annealing — Fundamentals

💡 Core Idea

SA is a probabilistic metaheuristic inspired by how metals slowly cool. When hot: accept worse moves freely (explore). As temperature drops: only accept improvements (exploit). This controlled cooling lets it escape local minima that trap greedy hill-climbers.

// Acceptance rule (Metropolis criterion): ΔE = E(new_state) − E(current_state) if ΔE < 0: always accept (new state is better) else: accept with probability exp(−ΔE / T) T decreases each iteration: T(k) = T₀ · α^k (α ≈ 0.995) When T is HIGH → exp(−ΔE/T) ≈ 1 → accept almost anything When T is LOW → exp(−ΔE/T) ≈ 0 → only accept improvements
// SA Algorithm (pseudocode) state ← random valid initial state T ← T_start (e.g. 100.0) best ← state for k in range(max_iterations): candidate ← perturb(state) # e.g. swap two elements ΔE ← cost(candidate) - cost(state) if ΔE < 0 or random() < exp(-ΔE / T): state ← candidate if cost(state) < cost(best): best ← state T ← T * α # cool down return best

Parallel Tempering (PT) — the upgrade

PT runs multiple SA chains simultaneously at different temperatures. Periodically, chains at adjacent temperatures attempt to swap states (Replica Exchange). Hot chains explore; cold chains exploit. Swaps allow good solutions found by hot chains to "sink" to cold chains.

// PT swap acceptance between chain i (T_i) and chain j (T_j), T_i < T_j: P(swap) = min(1, exp[(E_i − E_j) · (1/T_i − 1/T_j)]) Intuition: if swapping gives the colder chain a better state → always swap Otherwise → swap probabilistically (thermodynamic balance)
// PT — multiple replicas running in parallel ←──── Temperature ────→ Chain 1 [T=0.5] [T=1.0] [T=2.0] [T=5.0] ← hottest: explores freely ↑ "cold" ↑ "hot" Each chain runs SA independently. Every N_swap steps → try replica exchange between adjacent T chains: [Cold: state_A, E=−10] ⇌ [Hot: state_B, E=−6] If swap accepted: Cold gets state_B, Hot gets state_A → good structures "percolate down" to cold chains

How people use SA / PT

  • SA: quick classical baseline for any binary/combinatorial problem
  • PT: protein structure prediction (finding lowest energy conformations)
  • PT: hyperparameter optimization over large search spaces
  • PT: lead optimization in drug discovery — finding optimal SMILES edits
  • SA: VLSI placement, scheduling, neural architecture search
📌 SA vs PT — when to choose

SA is simpler and good enough for moderate problem sizes. PT is worth the added complexity when the energy landscape is rugged (many local minima) or when you have parallel compute available. In pharma: SA for fast screening, PT for thorough lead optimization.

✦ New Example: Clinical Trial Site Selection
🏥 PT Applied — Phase II Site Selection

Problem Setup

You have 20 candidate hospital sites for a Phase II clinical trial. You need to choose 6–8 sites that maximize patient recruitment while satisfying diversity, logistics, and cost constraints. The energy landscape is rugged: sites interact (overlapping patient catchments) — perfect for PT.

// State = binary vector s ∈ {0,1}²⁰ (1 = site selected) cost(s) = − Σ recruitment_i · s_i // maximize recruitment − λ₁ · diversity_score(s) // reward diverse geography + λ₂ · Σ overlap(i,j) · s_i · s_j // penalize patient overlap + λ₃ · total_cost(s) // penalize budget overrun + P · max(0, Σ s_i − 8)² // hard cap: ≤8 sites Perturbation: flip one s_i OR swap one selected/unselected pair

PT Setup (4 replicas)

// Parallel Tempering configuration Replica 1: T = 0.5 (cold — refines good solutions) Replica 2: T = 1.5 (warm) Replica 3: T = 4.0 (hot) Replica 4: T = 10.0 (very hot — escapes any local min) Each replica: - starts from different random valid selection - runs 5000 SA steps per "epoch" Every epoch: - try swap: Replica 1 ↔ Replica 2 (Metropolis swap rule) - try swap: Replica 2 ↔ Replica 3 - try swap: Replica 3 ↔ Replica 4 After 200 epochs: best state from Replica 1 = final selection
🔍 Why PT matters here

Site interactions (patient overlap penalties) create a rugged landscape. Pure SA often gets stuck choosing e.g. 5 sites in one region. PT's hot replicas discover that a cluster of 3 remote sites unlocks 40% more unique patients — this insight percolates down to the cold chain through replica exchange.

Code sketch

// Python sketch replicas = [State(T=0.5), State(T=1.5), State(T=4.0), State(T=10.0)] for epoch in range(200): for rep in replicas: rep.run_sa_steps(n=5000, cost_fn=site_cost) # Replica exchange (adjacent pairs) for i in range(len(replicas)-1): r1, r2 = replicas[i], replicas[i+1] ΔE = r2.cost - r1.cost ΔB = (1/r1.T) - (1/r2.T) # β = 1/T if random() < exp(ΔE * ΔB): r1.state, r2.state = r2.state, r1.state best_sites = replicas[0].best_state # coldest replica = best answer

③ VQE Variational Quantum Eigensolver

What is it, fundamentally?

💡 Core Idea

VQE is a hybrid quantum-classical algorithm for quantum chemistry. It uses the variational principle: for any trial quantum state |ψ(θ)⟩, the expectation value ⟨ψ(θ)|H|ψ(θ)⟩ is always ≥ the true ground-state energy E₀. So minimize ⟨H⟩ over θ and you get as close to E₀ as your ansatz allows.

Key difference from QAOA: VQE solves a physics problem (find lowest energy of a molecule) not a combinatorial problem (pick best items). The Hamiltonian here is the electronic structure Hamiltonian — real quantum mechanics, not a QUBO.

// Variational principle — the math foundation: E₀ ≤ ⟨ψ(θ) | H | ψ(θ)⟩ for ANY trial state |ψ(θ)⟩ VQE: find θ* = argmin_θ ⟨ψ(θ)|H|ψ(θ)⟩ Ansatz (UCCSD): |ψ(θ)⟩ = exp(T(θ) − T†(θ)) |HF⟩ - |HF⟩ = Hartree-Fock reference state - T(θ) = single + double excitation operators - θ = amplitudes tuned by classical optimizer (SLSQP)
// VQE Pipeline — step by step Molecule geometry (e.g. H₂, water, ligand fragment) │ ▼ PySCFDriver → Molecular Hamiltonian (fermionic operators) │ ▼ ActiveSpaceTransformer → freeze core electrons (keep 2e, 2 orbitals) │ reduces qubit count dramatically ▼ ParityMapper → fermionic ops → qubit Pauli operators │ parity mapping: saves 2 more qubits ▼ UCCSD Ansatz → parameterized circuit |ψ(θ)⟩ │ ▼ StatevectorEstimator → measures ⟨ψ(θ)|H|ψ(θ)⟩ on quantum sim │ ▼ SLSQP optimizer → updates θ to reduce energy │ ▼ Converged? → Yes → ground state energy E_VQE │ ▼ NumPyMinimumEigensolver → exact answer E_exact |E_VQE − E_exact| should be < 1 millihartree ✓

How people use VQE

  • Estimate ground-state energy of small molecules (H₂, LiH, BeH₂)
  • Compare binding energies of different conformers
  • Study reaction barriers (transition state energies)
  • Screen functional materials (battery electrolytes, catalysts)
  • Rank ligand-receptor interaction fragments by computed stability
⚠️ Current limitations

VQE on today's hardware needs active space reduction to ≤12 qubits — otherwise circuit depth overwhelms coherence time. On a simulator: up to ~20 qubits tractable. The UCCSD ansatz is chemistry-motivated and works well, but needs good Hartree-Fock starting state.

✦ New Example: Fragment Binding Energy Ranking
🧬 VQE Applied — KRAS G12C Fragment Screen

Problem Setup

You're doing fragment-based drug discovery against KRAS G12C. You have 5 small fragments identified from a crystallography screen. Each fragment binds in the same pocket. You want to rank them by electronic binding energy contribution using VQE on the fragment–cysteine interaction sub-system.

Why VQE? Not classical DFT?

For fragments with strong π–covalent interactions (especially covalent warheads attacking Cys12), DFT can misestimate correlation energy. VQE on the active space around the reactive bond gives a chemically accurate ground-state energy estimate. Educational demo — in practice you'd use CCSD(T) as reference.

Active Space Design

// Each fragment-Cys complex: Full system: ~200 electrons, ~400 basis functions (STO-3G) Active space: focus on the reactive bond region only 2 electrons, 2 spatial orbitals → 2 qubits after ParityMapper (saves 2) → circuit depth: shallow, laptop-runnable Frozen: all other electrons contribute via SCF mean-field Active: σ (C–S bond) and σ* (C–S antibond) only

Workflow

// VQE Fragment Ranking (5 fragments) For each fragment F in [F1, F2, F3, F4, F5]: 1. Load geometry: fragment + Cys12 sidechain (xyz coords from PDB) 2. driver = PySCFDriver(geometry=fragment_cys_xyz, basis='sto-3g') problem = driver.run() 3. transformer = ActiveSpaceTransformer(num_electrons=2, num_spatial_orbitals=2) reduced_problem = transformer.transform(problem) 4. mapper = ParityMapper(num_particles=reduced_problem.num_particles) H_qubit = mapper.map(reduced_problem.second_q_ops()[0]) # H_qubit is now a 2-qubit Pauli Hamiltonian 5. ansatz = UCCSD(num_spatial_orbitals=2, num_particles=(1,1), qubit_mapper=mapper) ansatz.initial_state = HartreeFock(...) 6. vqe = VQE(estimator=StatevectorEstimator(), ansatz=ansatz, optimizer=SLSQP(maxiter=100)) result = vqe.compute_minimum_eigenvalue(H_qubit) E_vqe[F] = result.eigenvalue.real # in Hartree 7. E_exact[F] = NumPyMinimumEigensolver().compute_minimum_eigenvalue(H_qubit) error[F] = |E_vqe[F] - E_exact[F].real| Ranking: sort fragments by E_vqe (lowest = most stabilized = best binder) Result: F3 < F1 < F5 < F2 < F4 → F3 is the priority fragment
Energy here is in Hartree. 1 Hartree ≈ 627.5 kcal/mol. Errors below 1 millihartree = "chemical accuracy".
✅ Output

Fragment F3 has the lowest active space energy (−1.1372 Ha vs F4 at −1.1284 Ha) → selected for further derivatization. The VQE error vs exact is <0.5 millihartree for all fragments.

Decision Guide — which to reach for?

// Mental model: "I need to PICK THE BEST SUBSET from a list of options" │ ├─ fewer than ~20 items, have quantum hardware/sim → QAOA │ (encodes problem as QUBO, quantum circuit finds answer) │ ├─ many items (50–10,000), classical compute only → SA or PT │ SA: one shot, fast | PT: rugged landscape, parallel compute │ └─ not a selection problem, I need to know a molecule's ENERGY → VQE ├─ small active space (≤12 qubits) → run on simulator └─ rank molecules by stability / binding affinity

Common Gotchas

  • QAOA: penalty weight P must be large enough to enforce constraint, but not so large it drowns out the objective. Rule of thumb: P ≈ 5 × max(score_i).
  • SA: choosing T_start and α is an art. Too fast cooling → stuck in local min. Too slow → wastes compute. Set T_start ≈ 10 × typical ΔE of a random move.
  • PT: acceptance rates between replicas should be ~20–40%. If near 0 or 100%: adjust temperature spacing. Geometric spacing (T_k = T₀ · r^k, r≈1.5–3) usually works.
  • VQE: the UCCSD ansatz can fail if the Hartree-Fock reference is a poor starting point (strongly correlated systems). Check ⟨HF|H|HF⟩ vs E_exact first.
Good luck! The algorithms are tools — the problem formulation is the hard part.
